## Выполненные исправления

### 1. P1 — закрытые панели и полные инструкции: выполнено

**Было:** главная всегда монтировала `NewProgramSheet`, чей `useExercises()` получал полные en/ru инструкции даже при закрытой панели. Русский текст запрашивался после завершения core Promise. Каталог ожидал примерно 1,97 МБ JSON.

**Сделано:** [ProgramsPage](../src/features/programs/ProgramsPage.tsx) монтирует создание программы только при открытии. Закрытый [ExercisePicker](../src/features/programs/ExercisePicker.tsx) не загружает данные и не строит индекс. [build-data.ts](../scripts/build-data.ts) генерирует отдельные `exercise-names.json`; каталог, программы и тренировка используют названия. Полные `exercises.json` остаются целевым ресурсом подробной техники, а не форматом совместимости.

[Хранилище упражнений](../src/entities/exercise/store.ts) запрашивает метаданные и названия обоих языков параллельно, переиспользует Promise по языку, допускает повтор после неудачной загрузки и защищается от устаревшего ответа при смене языка. Инструкции загружаются отдельным `useExerciseText()` только на открытой странице или в открытой технике; на время ожидания показано сообщение загрузки. Английские названия и техника служат fallback.

**Проверено:** пять тестов загрузчика покрывают параллельность, дедупликацию, смену языка, повтор после ошибки и fallback инструкций. До отключения браузерного инструмента на локальной главной подтверждены только запросы UI; каталог открывался с 968 названиями. Последующие изменения проверены тестами и сборкой.

### 2. P1 — рендеры активной тренировки: выполнено

**Было:** `useElapsed()` жил в `ActiveWorkout`, поэтому каждую секунду заново строились карточки и выполнялся поиск предыдущих подходов. Подписки на весь session/settings store оповещали все карточки при изменении одного подхода.

**Сделано:** в [WorkoutPage](../src/features/workout/WorkoutPage.tsx) часы вынесены в `ElapsedTime`. [ExerciseCard](../src/features/workout/ExerciseCard.tsx) мемоизирован, действия и настройки выбираются селекторами, предыдущие результаты мемоизируются по истории, упражнению и схеме повторов. [CardsView](../src/features/workout/CardsView.tsx) передаёт стабильный callback завершения подхода. Подписки [RestTimerBar](../src/features/workout/RestTimerBar.tsx) также сужены до используемых значений.

**Проверено:** [рендер-тесты](../src/features/workout/WorkoutPage.test.tsx) монтируют реальные карточки в обоих видах с 12 упражнениями и историей из 1 000 тренировок. За 30 секунд fake timers карточки не рендерятся от часов; изменение одного подхода обновляет только одну карточку. Запуск отдыха и изменение звука не рендерят остальные карточки. Счётчик размещён в тестовой замене изображения внутри реальной карточки; это не профиль длительностей React commit.

### 3. P2 — повторное сохранение архива: выполнено

**Было:** стандартный Zustand persist сериализовал весь session store после каждого `set`, включая историю. Отметка подхода и запуск отдыха выполняли два таких сохранения.

**Сделано:** [sessionStorage](../src/entities/session/storage.ts) сохраняет `active/rest` в `fitnoss:workout`, а архив — в `fitnoss:history`, только при изменении соответствующих ссылок. [toggleSet](../src/entities/session/store.ts) меняет подход и отдых одним обновлением. Архив записывается при завершении, редактировании, удалении, возобновлении и импорте истории. При завершении архив записывается раньше очистки активного снимка.

Это новый внутренний формат localStorage. Старый ключ `fitnoss:sessions` не читается: согласно стадии продукта совместимость и миграция не добавлялись. Формат экспортируемого бэкапа не менялся. Архив пока остаётся в localStorage; переход на IndexedDB при необходимости большего объёма — отдельное будущее изменение.

**Проверено:** [тесты store](../src/entities/session/store.test.ts) проверяют одну сериализацию без поля history при отметке подхода, независимое сохранение правок истории, восстановление активной тренировки и отдыха, finish/resume и незавершённый план. Тесты бэкапа проходят. Для модельного снимка из 8 упражнений × 4 подхода ввод сериализует 1 667 байт независимо от размера архива; численные времена в JSON — микробенчмарк Node, без стоимости браузерного localStorage.

### 4. P2 — стартовый граф маршрутов: выполнено

**Было:** каталог, редактор программы, тренировка, журнал, настройки и About входили в начальный статический граф. Считая preload-чанки, JS занимал около 569 КБ без сжатия.

**Сделано:** [App](../src/app/App.tsx) оставляет стартовыми главную и каркас, остальные страницы подключает через `lazy`. Создание программы также загружается динамически. [Layout](../src/app/Layout.tsx) показывает локализованный статус загрузки внутри содержимого, сохраняя навигацию. Создание программы имеет собственную Suspense-границу. Вкладка «Ещё» по-прежнему открывает настройки напрямую.

**Проверено:** TypeScript/Vite build проходит, маршруты выпускаются отдельными чанками. Скрипт аудита суммирует все JS/CSS, объявленные в HTML, включая modulepreload. Стартовые JS/CSS сократились на 44,44 КБ gzip. Это сокращение файлов и стартового выполнения, а не измеренное улучшение LCP.

### 5. P2 — анимации изображений: выполнено

**Было:** каждый `ExerciseImage` по умолчанию монтировал два кадра и отдельный интервал; невидимые карточки продолжали выполнять React-обновления. Все кадры, включая главное фото, имели `loading="lazy"`.

**Сделано:** [ExerciseImage](../src/shared/components/ExerciseImage.tsx) по умолчанию показывает одну статическую миниатюру. Большие фотографии открытой техники и карточек явно включают анимацию. Интервал работает только при пересечении viewport, видимой странице и разрешённом motion; обработчики и observer очищаются при размонтировании. Первый кадр главного фото имеет eager/high, второй остаётся lazy.

**Проверено:** [DOM-тесты](../src/shared/components/ExerciseImage.test.tsx) проверяют один кадр без таймеров у миниатюры, смену кадров большой фотографии, остановку вне viewport, скрытие вкладки, изменение reduced motion и приоритет первого кадра. Визуальное качество переходов и фактический LCP-элемент на физическом устройстве повторно не измерялись.

### 6. P2 — растущий DOM журнала: выполнено

**Было:** `history.map()` выводил весь архив; records и mine рассчитывались даже на вкладке истории.

**Сделано:** [JournalPage](../src/features/journal/JournalPage.tsx) использует [PaginatedList](../src/shared/ui/paginated-list.tsx) по 20 строк для истории, рекордов и своих упражнений. Есть локализованные переходы, номер страницы и возврат к началу списка при смене страницы. Поиск сбрасывает страницу; сокращение списка не оставляет пустую несуществующую страницу. Records/mine вычисляются только для соответствующей вкладки; недельная карта мемоизирована.

**Проверено:** [тест пагинации](../src/shared/ui/paginated-list.test.tsx) проверяет ограничение до 20 строк на 1 000 элементах, переход вперёд и корректный показ после сокращения списка до пяти элементов. Статистика и графики сохраняют существующие функциональные тесты.

## i18n и офлайн

Список языков и английский UI включены в сборку. [Тест i18n](../src/shared/i18n/index.test.ts) подтверждает один запрос русского UI без `index.json` и без сетевого запроса en fallback; переключение на английский не делает запрос.

Все ленивые JS, CSS, основные шрифты, названия, полные инструкции и UI остаются в precache. Скрипт аудита проверяет сгенерированный `sw.js`: **69 записей, отсутствующих обязательных ресурсов — 0**. Изображения и Windows-флаговый шрифт по-прежнему кэшируются при использовании.

Объём полного precache **вырос с 2 922 до 3 099,65 KiB** до транспортного сжатия: добавлены компактные проекции названий, чанки и загрузчики. Это осознанный обмен ради меньшего объёма критических данных при сохранении полной офлайн-установки. Общий трафик первой установки не заявляется уменьшенным. Проверка манифеста не заменяет отдельный браузерный сценарий установки/отключения сети.

```powershell
npm run data -- --check

npm run build
npm test
node scripts/perf-audit.mjs
```

Финальная сборка успешна. Проверка переводов: UI ru **477/477**. Тесты: **20 файлов, 92 теста**, включая 13 новых относительно исходного аудита. Добавлен jsdom как зависимость разработки для DOM-проверок; в runtime приложения он не входит.

Скрипт рассчитан на текущие имена en/ru файлов и структуру Workbox-манифеста. Настройки стемминга/MiniSearch в нём повторяют реализацию приложения и требуют синхронизации при изменении поиска. Микробенчмарки выполнены в Node 25.2.1, Windows x64: 10 прогревочных и 100 измеряемых итераций. Сырой baseline сохранён отдельно и не перезаписан.

LCP, INP, CLS, TBT, Chrome Coverage и длительности React commit **не измерены**. Браузерный инструмент стал недоступен в ходе работы; окончательная проверка поведения выполнена через jsdom, реальные stores, fake timers и production build. Не присваиваем Lighthouse score и не переводим сокращение байтов в обещанный выигрыш миллисекунд. Для отдельной проверки на устройстве: холодный запуск и установленный SW, главная/каталог, оба вида тренировки, большой журнал, затем запуск без сети.
